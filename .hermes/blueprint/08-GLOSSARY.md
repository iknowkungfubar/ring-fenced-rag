# Glossary

## Domain Terms

| Term | Definition |
|------|------------|
| **Ring-Fence** | The security boundary that prevents unauthorized access to document chunks. Enforced at the database level via JSONB metadata filtering, not at the application layer. Named after the original design document's metaphor of a physical fence around proprietary data. |
| **Chunk** | A segment of a document, typically 256-1024 tokens. Documents are split into chunks before embedding and indexing. Each chunk carries full metadata including `allowed_roles`. |
| **Embedding** | A dense vector (list of floats) representing the semantic meaning of a text chunk. Generated by a sentence-transformer model. Cosine distance between embeddings measures semantic similarity. |
| **pgvector** | PostgreSQL extension that adds vector similarity search. Supports HNSW and IVFFlat indexes for efficient approximate nearest neighbor search. |
| **LCEL** | LangChain Expression Language. A declarative pipeline syntax using the `\|` pipe operator to chain runnables. This project uses ONLY LCEL, never legacy wrapper chains like `RetrievalQA`. |
| **allowed_roles** | A JSON array in each chunk's metadata specifying which user roles are permitted to retrieve this chunk. Enforced by the SQL `@>` JSONB containment operator. |
| **SQLRecordManager** | LangChain utility that tracks document content hashes in a SQL table. Used for idempotent indexing — prevents duplicate vectors when the same content is ingested multiple times. |
| **Idempotent Ingestion** | An ingestion pipeline that produces the same state regardless of how many times it's run. Running `ingest` on unchanged documents always results in exactly one copy. |
| **Degraded Mode** | Query mode when the LLM is unavailable. Returns retrieved context with a "no LLM available" message instead of a generated answer. |
| **Standalone Mode** | Running RFR without Docker. Uses SQLite (brute-force vector search) and direct httpx to a configured LLM. Suitable for testing and light use. |
| **Role** | A string identifier (e.g., `"senior_engineer"`, `"admin"`) that maps to document access permissions. Derived from the API key at request time. Not a full user account system — v1 uses API key → role mapping. |

## Conventions

| Convention | Rule |
|------------|------|
| **Variable naming** | `snake_case` for Python, `camelCase` for TypeScript |
| **API key format** | `rfr_<32-hex-chars>` — prefix identifies the system |
| **Error code format** | `SCREAMING_SNAKE_CASE` |
| **Database table names** | `snake_case`, plural |
| **JSON field names** | `snake_case` in API responses |
| **Migration naming** | `V<NNN>_<description>.py` |
| **Git commit style** | Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` |
| **Version number** | `MAJOR.MINOR.PATCH` (SemVer) |
| **Config key format** | `dot.separated.path` (e.g., `llm.provider`, `ingestion.chunk_size`) |
| **Role names** | `snake_case`, lowercase (e.g., `senior_engineer`, not `Senior Engineer`) |

## Reserved API Key Roles

| Role | Permissions |
|------|-------------|
| `admin` | Full access: create/revoke keys, trigger ingestion, delete docs, query any role-matching docs |
| (any custom role) | Query access only: can query docs where `allowed_roles` includes this role |
